# Why LambdaFlux

Fusion-material discovery makes functional programming concrete because the scientific workflow is mostly transformation of evidence under explicit constraints.

| Scientific problem | Functional concept |
|---|---|
| Normalize alloy fractions | pure functions and referential transparency |
| Carry validation failures | `Result`/Either and monadic bind |
| Aggregate property streams | `foldl`, `foldr`, and monoids |
| Update one nested property | lawful lenses over frozen dataclasses |
| Combine competing objectives | product types, predicates, and Pareto partial orders |
| Select the next experiment | composition plus uncertainty-aware acquisition |
| Preserve evidence lineage | immutable values and repository boundaries |
| Explain results locally | deterministic evidence before Ollama generation |

The project is useful without pretending to solve fusion materials qualification. It teaches how to construct an auditable early-screening service that narrows candidates for simulation or experiment, makes assumptions visible, and preserves the difference between calculated, measured, synthetic, and inferred properties.
